# The Mac app

The Mac app is the same Flask app as `app.py`, packaged with
[PyInstaller](https://pyinstaller.org) into a standalone `yt2mp3.app` and shipped
as a DMG. Nothing needs to be installed on the Mac that runs it — Python, Flask,
yt-dlp and ffmpeg are all inside the app bundle.

## How it works

| File | Role |
|---|---|
| `mac_app.py` | Entry point for the app. Starts the Flask server on a random free port (localhost only) and shows the page in a native window using [pywebview](https://pywebview.flowrl.com) (WebKit). Closing the window quits the app. |
| `app.py` | The Flask app. When running inside the bundle (`sys.frozen`), it reads templates from the bundle and saves MP3s to `~/Downloads/yt2mp3` (the bundle itself is read-only). It uses the ffmpeg path from `YT2MP3_FFMPEG`, which `mac_app.py` sets to the bundled copy. |
| `templates/index.html` | The UI. It detects the app window (`window.pywebview`) and swaps browser-only actions for native ones: track links become **Show in Finder**, **Save all as .zip** opens a native Save dialog, and a **Downloads** button opens the folder. In a normal browser it behaves as a web page. |
| `build_mac.sh` | Builds the app and DMG (see below). |
| `assets/icon.icns` | App icon, generated by `assets/make_icon.py`. |

The page talks to the native side through pywebview's JS bridge: the `Api`
class in `mac_app.py` exposes `open_folder()`, `reveal(filename)` and
`save_zip(job_id)` as `window.pywebview.api.*`.

### ffmpeg

Homebrew's ffmpeg links against dozens of Homebrew-only libraries, so it can't be
copied into the app. Instead the build uses the static ffmpeg binary that ships
in the [`imageio-ffmpeg`](https://pypi.org/project/imageio-ffmpeg/) wheel for the
target architecture. It only depends on system libraries and includes the MP3
encoder (libmp3lame).

## Building locally

```bash
./build_mac.sh          # Apple Silicon -> dist/yt2mp3-AppleSilicon.dmg
./build_mac.sh intel    # Intel         -> dist/yt2mp3-Intel.dmg
./build_mac.sh all      # both
```

Each build uses its own virtualenv under `build/` (your `venv/` isn't touched)
and always installs the latest yt-dlp. Output:

- `dist/arm64/yt2mp3.app`, `dist/x86_64/yt2mp3.app` — the apps
- `dist/yt2mp3-AppleSilicon.dmg`, `dist/yt2mp3-Intel.dmg` — the DMGs (app + Applications shortcut)

**Intel builds on an Apple Silicon Mac** run under Rosetta. Homebrew's Python is
arm64-only and Apple's built-in Python (3.9) is too old for yt-dlp, so the
script downloads a standalone x86_64 Python 3.12 from
[python-build-standalone](https://github.com/astral-sh/python-build-standalone)
into `build/py-x86_64/` the first time.

To try a build without installing it:

```bash
open dist/arm64/yt2mp3.app
```

## The icon

`assets/make_icon.py` draws the icon with Pillow and writes `assets/icon.png` and
`assets/icon.icns`. Both are committed, so you only need to rerun it if you
change the design:

```bash
./build/venv-arm64/bin/pip install pillow
./build/venv-arm64/bin/python assets/make_icon.py
```

## Signing

The app is ad-hoc signed only (PyInstaller does this automatically), so macOS
Gatekeeper warns on first launch — see "First launch" in the README. Removing
the warning requires an Apple Developer Program membership ($99/year) to sign
with a Developer ID certificate and notarize the app.
